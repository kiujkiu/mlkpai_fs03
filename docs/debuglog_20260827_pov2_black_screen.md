## 2. 🎯 根因：供电

一条因解释全天所有现象：

| 现象 | 供电解释 |
|---|---|
| 屏全黑一整天 | 面板供电不足 / 掉电 |
| USB WiFi 网卡反复掉出总线（`usb 1-1: USB disconnect` #5 @114s, #6 @499s） | VBUS 跌落 |
| `ci_hdrc` rebind + USB PHY 硬复位都救不回网卡 | 软件层面本来就修不了 |
| **串口适配器 COM8/COM9 反复从 PC 上消失** | **CH342 在板子上、靠板子供电 ⇒ 它消失 = 板子掉电** |
| P1 无输出 / P3 红色不对 | 余量不够时先掉压降最高的通道 |
| 08-26「蓝色不亮」 | 蓝的正向压降最高，最先带不动 |

### 🔴 最有价值的判据

**「串口适配器从 PC 上消失」是板子掉电最快最硬的判据** —— 因为 CH342 是板载的、靠板子供电。
以后板子失联：**先看 COM 口在不在**。在 ⇒ 板子有电（查网络）；不在 ⇒ **板子没电**（别查软件）。

### 🔴 方法论教训

**多个不相干子系统同时出问题（屏 / USB 网卡 / 串口芯片），先量供电。**
单一软件 bug 不会同时打掉这三样。我这一天在软件上追的十几个假设，全部是在追一个硬件故障的影子。

## 3. 过程中挖出的真实缺陷（副产品）

### ① `pov_boot.sh` 取帧顺序 bug —— 已修 (`7a8e478`)

```
pov_boot.sh:123  pw(0x10,(142<<16)|0x5)       ← pov_en=1, 触发全机唯一一次取帧
pov_boot.sh:151  pw(0x0C,(1<<30)|…|(1<<16))   ← bpp_mode=1 到这里才打开, 晚了 28 行
```

`pov_dual_top.v:387` 只有 `slice_idx` 变化才重取帧；台面无电机 + sensor 模式下
`angle_tracker.v:103` 的 `track_en=0` ⇒ `slice_idx` 定格 ⇒ **fb 一辈子只被写那一次**。
那次 `bpp3_r` 还是复位值 0，按 1-bit 布局写（只写 plane0，最大 fb 地址 429）；
随后 `bpp_mode=1`，引擎按 `pack_addr=row*18+plane*6+word` 读 0..971
⇒ **972 个读地址里 542 个（56%）从没被写过 = 恒 0**。

转起来时 `pov_rxd`/fake-spin 每片都重取，bug 被完全掩盖 —— **只在台面调试时致命**。

**修法**：sub01 之后补一次 `pov_en` 0→1 脉冲（`!pov_en` 会把 `df_last_slice` 复位成
`0xFFFF`，`pov_dual_top.v:417-421`）。⚠ `[31:16]` 必须写 0，只有非零才改 `n_slices`
（`pov_dual_top.v:335-336`）。

### ② WiFi 等不到网卡就永久放弃 —— 已修并**实测救回一次** (`7a8e478`)

`pov_boot.sh` 等 `^wl` 接口 30 秒，等不到就 `NO_WLAN_STATIC_ONLY; exit 0`，**之后再无任何补救**。
实测 mt7921u 有过 **403 秒**、**460 秒**才枚举的情况。

**修法**：转后台守候，每 5s 查一次、最多 20 分钟。
**实测生效**：某次开机日志 `NO_WLAN_YET -> 转后台守候` → `LATE_WLAN_UP wlx90de8047f0ff (开机后约 460 秒才出现)`。
老代码在这里会永久失联，只能插串口救 —— 今天上午就被卡住两次。

### ③ `pov6_hold.py` / `pov6_fake.py` 砸 `n_slices`

它们写 `0x10` 时带 `(360<<16)`，**每次都把 `n_slices` 从 142 砸成 360**。
正确写法是 `[31:16]=0`（表示"不改"）。

### ④ 3-bit 下 AXI fb 窗只写得进 plane0

```verilog
fbw_plane = pov_en ? df_fb_wplane : 2'd0     // pov_dual_top.v:548-551
```

`pov6_*` 工具走的 AXI fb 窗 plane 号硬钉 0。`bpp_mode=1` 时引擎按
`pack_addr = row*18+plane*6+word` 读 ⇒ **plane0 全覆盖 / plane1 只中顶部 1/3 /
plane2 一个字都写不进**，而 plane1+plane2 占总光通量 **74%**。

⇒ **台面上用 pov6 工具前必须先 `pw(0x0C,0x40000000)` 把 `bpp_mode` 清成 0**，
否则看到的东西没有意义。今天那唯一一次"亮"看到的叠影就是这个机制。

### ⑤ `pov_rxd` 是隐形的第二个 writer

每帧调 `bcm_apply()` 重写 `0x0C sub01`（含 `bpp_mode`），不变也会在
`BCM_REASSERT_EVERY(=256)` 时强制重申 ⇒ **11 fps 下最迟约 23 秒把 `bpp_mode` 掀回 1**，
且回读不符时**只打日志不重写**，串口上看不见。
⇒ 手动清 `bpp_mode` 前必须 `systemctl stop povrxd`（`Restart=always`，kill 会被拉起来）。

### ⑥ `board_ssh.sh` 的两个雷

- 默认解析 `pov.local` → **指向第一台 pov**（别人在用）。操作 pov2 必须显式 `BOARD_IP=`
- 注释写 "pov2 … ICND2049 单面"，**错的**，实为 ICND2047 偏心双屏

### ⑦ `fs03_card.img.gz` 里是未打补丁的 `pov_boot.sh`

镜像是 08-26 做的（13941 B）。**重烧卡会丢掉 08-27 的两个补丁**，重烧后要重新部署。

## 4. 被推翻的假设（含我自己的推理错误）

| 假设 | 怎么排除的 |
|---|---|
| FS03 跳帽 `J1 (ADJ_BANK13)` 掉了/跳 1.8V | DCLK 在 J1 上有波形 ⇒ 同 bank 引脚是活的 |
| 卡上 BOOT.BIN 版本不对 | 镜像逐字节确认；且 prelz4 与 lz4x3 的 panel core 是同一套 RTL |
| ICND2047 掉电需重配 | 手册 P15 REG1 默认 `0xf`=满增益；且现役 bitstream **没有写这两个寄存器的通路** |
| OE 极性反了 | 手册 P12 / RTL `oe_r` 语义 / 亮度与 `oe_window` 单调正相关 / 原理图无反相元件，四条独立证据 |
| `sdi_mask` 被清 / lane 映射错 | 9 条 lane 是 9 个独立 ball、9 条独立级联链，RTL 里无数据相关分支 |
| 单纯亮度太低 | oe=111(56.9%) / oe=187(69%) / oe=184(55%) 都黑，而记忆里"看不见"的门槛是 4% |
| **「第 5 次 oe 最低反而亮 ⇒ 亮度不是变量」**（我的推理） | **前提算错了**：两个脚本只写 `sub10` 的 `oe_window`（= **plane0 权重**），`oe_w1/w2` 恒为 92/46。真实占空 oe=8/bpp1 是 **24.96%**，属中间水平，不是最暗 |
| **「J1 上 RGB 平 = 没数据」**（我的推理） | **错**。纯色实心时 SDI 就是直流，示波器上本来就该平。"RGB 没波形"从来不是故障证据 |
| **「`frame_period=31590` 证明引擎在扫」**（我的推理） | **错**。它是帧末锁存的**残值**，引擎卡死也不归零。但它**变化**时有效（1-bit/oe48 = 10530、1-bit/oe187 = 14634、3-bit = 31590，全部精确吻合） |
| **「`oeprobe` 证明信号是好的」**（我的推理） | **错**。`oe_state_o` 是 ODDR **输入端**的 fabric 镜像，`icnd2047_panel_core.v:132` 原话「pad 是 ODDR，不可回采」。DCLK/LE/SDI/行驱三线同样全经 ODDR，**十二根线一根都不可回采**。它只证明"引擎 A 的状态机在按正确参数跑" |

## 5. 好用的判据（本次验证有效）

- **`frame_period` 随配置变化** = 配置真的落地 + 引擎在实时重算
  - 3-bit → `31590` (162×195) ／ 1-bit oe=48 → `10530` (54×195) ／ 1-bit oe=187 → `14634`
- **`PLDIAG eng=3/3`** = PL 里是 `lz4x3`；三引擎全判死 = `prelz4`。**判定 bitstream 版本最硬的只读特征**
- **`0x24` 影子回读**判 POV_CTRL 各位（`0x10` 是纯写口，读回是 `slice_idx`）
- **`slice_idx` 推进速率**对账转速：142 片 × 12 rev/s = 1704 片/s，40ms 应走 68.2 片
- **串口 COM 口在不在** = 板子有没有电

## 6. 装机固化清单

见记忆 `project_pov2_shipping_config.md`。要点：

| 项 | 值 | 备份 |
|---|---|---|
| 卡上 `BOOT.BIN` | `BOOT.bin.lz4x3` md5 `67894f9c…` | `/home/uisrc/BOOT.BIN.prelz4.bak` |
| `pov_boot.sh` | `BPP3=1` (3-bit / oe_w 184 92 46 / n_slices 142) | `pov_boot.sh.pre20260827.bak` |
| `povrxd` drop-in | 出厂版，**无 `--fake`**（走光电传感器） | `idle.conf.fake.bak` |
| 自启 | `pov` + `povrxd` enabled，`povcolors` disabled | `povcolors.service.bak` |

🔴 **`--fake` 装机陷阱**：台面无电机时加的软件伪造转速，装到真机上必须去掉，
否则屏按假转速刷、与实际转速无关 ⇒ 体显示全糊。
配套坑：`pov_rxd` 不带 `--fake` 时**根本不写 `0x10`**，`fake_en` 会留残留，要靠 `pov_boot.sh` 开机写回。

**写启动分区的正确姿势**：先传 rootfs 校验 md5 → 通过了才写 FAT → 写完 `sync` →
**umount + 只读重挂复校**（绕开页缓存假阳性）。
