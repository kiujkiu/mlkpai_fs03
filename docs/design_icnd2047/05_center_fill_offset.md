# 05 — 消除中心黑柱: 整体平移使屏A 穿心 (2026-07-30)

分支 `feature/offset-axis-center-fill`。起点 `10e6a72`。

## 0. 问题与约束

**现象**: 屏中心有一根黑柱, 直径 13.8 mm (14.7 px, 占屏宽 9.3%, 占截面积 0.85%)。

**成因**: 两屏背靠背、关于转轴对称各偏 6.9 mm ⇒ 半径 < 6.9 mm 的圆柱**永远扫不到**。
几何固有, 见 `project_pov3d_offset_axis_geometry`。

**约束**: 13.8 mm 间距是 **两块 PCB + 散热/结构件的物理下限**, 机械上压不下去 (用户 2026-07-30 确认)。

## 1. 先否掉的方案

### ① 缩小间距 — 机械封死

盲区半径 = 间距/2, 线性关系。间距压到 5-6 mm 盲区只剩 ~5 px 基本看不见, **零软件改动**,
是最优解 —— 但物理上做不到。

### ② 内容偏心规避 — 算下来不实用

盲区是圆柱形, 只影响正好在转轴上的内容。把模型整体偏心 (`--x-offset`) 即可完全避开。
**但代价过大**:

```
模型半径 R 要完全避开: 偏心量 >= R + 7.36 px, 同时 R + 偏心 <= 79.8 px (不出界)
⇒ 只有 R <= 36 px 的模型能做到 (仅占屏宽 46%)
```

现有内容半径 70-80 px (吃满体积)。**为藏 9.3% 的黑柱要把显示尺寸砍掉一半以上, 不划算。**

## 2. 采用方案: 整体平移 6.9 mm, 让屏A 穿心

```
平移前  屏A +6.9mm / 屏B -6.9mm   (关于轴对称)
平移后  屏A   0mm  / 屏B -13.8mm  (屏A 穿过转轴)
```

- 屏A 穿心 ⇒ 覆盖整个圆盘, **中心不再全黑** ✅
- 屏B 盲区半径翻倍到 13.8 mm

### 🔴 代价必须认清: 黑柱 → 更宽的暗柱

每转命中次数:

| 区域 | 命中/转 | 相对亮度 |
|---|---|---|
| 外圈 r > 13.8 mm | 屏A 2 + 屏B 2 = **4** | 100% |
| 中心 r < 13.8 mm | 仅屏A **2** | **50%** |

**用 9.3% 屏宽的全黑, 换 18.4% 屏宽的半亮** (面积 0.85% → 3.4%)。
且 r = 13.8 mm 处有一圈**亮度硬边界**, 人眼对此敏感, 可能比黑柱更扎眼。

⚠ **这是观感权衡, 不是纯技术改进。上板实拍对比后再决定是否保留。**

### 对称性丢失 ⇒ 必须两套数据

屏B 的平面永远不等于屏A 的任何平面 ⇒ `屏B@θ ≡ 屏A@(θ+180)` **不再成立**,
两屏不能再共用同一份 360 片。这是 [[project_pov3d_offset_axis_geometry]] 里
"RAM 不用两块" 结论的**失效条件**, 现在真的触发了。

## 3. 实施

### 3.1 渲染两套 (host)

```bash
povstream.py render ... --gap-mm 0    --out-dir frames_X_A   # 屏A 穿心
povstream.py render ... --gap-mm 27.6 --out-dir frames_X_B   # 屏B 偏 13.8mm
```
⚠ `--gap-mm` 语义是**两屏间距**, 单屏偏移 X mm 要传 `2X`。

### 3.2 省 25% 带宽的优化: 屏A 只存 180 片

屏A 穿心时 `slice i` 与 `slice i+180` **互为镜像** ⇒ 只需存 180 片, 另一半用硬件镜像生成。
`mirror_a` 已在 RTL 里 (2026-07-28 加), 只需加一条:

```verilog
wire mirror_a_eff = mirror_a ^ (slice_idx >= 9'd180);   // 后半圈自动翻
// 取帧地址同时对 180 回绕
```

```
朴素   360(A) + 360(B) = 8.44 MB/体积帧   带宽 2.0×
优化   180(A) + 360(B) = 6.33 MB/体积帧   带宽 1.5×  ← 省 25%
```

### 3.3 DDR 布局 (mem=256M 预留 0x10000000..0x1FFFFFFF)

现在 bank A/B 是**同一内容的双缓冲**; 改后需 2 内容 × 2 缓冲 = 4 bank:

| bank | 地址 | 内容 |
|---|---|---|
| 0 | `0x10000000` | 屏A 内容 buf0 |
| 1 | `0x10500000` | 屏A 内容 buf1 |
| 2 | `0x10A00000` | 屏B 内容 buf0 |
| 3 | `0x10F00000` | 屏B 内容 buf1 |

步距维持 `0x500000` 便于换算; 顶到 `0x11338000`, 距 256 MB 上限还剩 **237 MB**。

### 3.4 RTL 改动

现状: fetch 只有一个 `slice_base` 入口 (`pov_dual_top.v:404 .slice_base(base_lat)`),
pair FSM 的 A/B 两次取帧共用 `base_lat` (pair 级快照保证翻页原子性)。

改动:
- 新增 `0x2C = slice_base_B` 寄存器 (屏B 内容基址)
- pair FSM 按 `target` 选 `base_lat_A` / `base_lat_B`, **两者在 idx 变化那拍同时快照** (保持原子性)
- 新增 `0x10[6] = half_a` (屏A 180 片模式), 配合 `mirror_a_eff` 与地址回绕
- 状态回读加 `0x00[15] = half_a` (照 [[feedback_verify_signal_actually_connected]] 的教训,
  新功能一律留回读位)

### 3.5 pov_rxd 改动

- 一个体积帧现在是**两段数据** (A 段 + B 段), 协议要能区分。最小改动: 复用 PVS1 头的
  保留位标 `SEG_A`/`SEG_B`, 发送端连发两段, 板端收齐两段才翻页
- 4 bank 轮转, `FRAME_MAP_LEN` 与 `BANK_STRIDE` 相应扩大
- ⚠ 解码量翻 1.5×, **本来就是瓶颈** (逐帧 ACK, 见 [[feedback_povrxd_stop_and_wait_limit]])

## 4. 顺序建议

1. **先做推流流水线** (window=2, +62% 帧率) 腾出带宽余量 — 否则 1.5× 数据量压上来会很难受
2. RTL: `slice_base_B` + `half_a` + `mirror_a_eff`
3. host 渲两套 + pov_rxd 双段协议
4. **上板实拍对比**: 现状(黑柱) vs 平移后(暗柱), 观感说了算

## 5. 回滚

`slice_base_B` 写成与 `slice_base` 相同、`half_a=0` ⇒ 行为完全回到现状 (两屏共用一份)。
机械也要移回对称位置。
